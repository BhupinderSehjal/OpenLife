# Issue Labels Guide



## Purpose



This guide explains how maintainers should use repository labels consistently.



## Common Labels



### frontend



Use for user interface, React, styling, and client-side issues.



Example:



* Add mobile navigation access to new frontend pages



### backend



Use for server-side, database, authentication, and API implementation issues.



Example:



* Remove backend startup debug logs



### documentation



Use for README updates, guides, checklists, and contributor documentation.



Example:



* Add deployment checklist for maintainers



### good first issue



Use for small, beginner-friendly tasks that help new contributors get started.



### Beginner Friendly



Use for issues that do not require deep project knowledge.



### help wanted



Use when maintainers are actively seeking community contributions.



### api



Use for API routes, request validation, authentication, and response behavior.



Example:



* Add API examples for auth routes



### discussion



Use for topics that require feedback, planning, or community input before implementation.



## Labeling Tips



* Apply labels consistently.

* Use multiple labels when appropriate.

* Keep labels updated if issue scope changes.

* Mark beginner-friendly issues clearly.



## Maintainer Checklist



* Correct labels applied.

* Issue category identified.

* Beginner-friendly issues marked.

* Documentation issues labeled appropriately.

* Duplicate labels avoided.
